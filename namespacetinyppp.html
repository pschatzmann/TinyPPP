Detailed Description

TinyPPP internals: PPP engine, HDLC framing and the IP stack.

TinyPPP: header only PPP (Point-to-Point Protocol) networking over any Arduino Stream (USB serial, UART, ...).

Implementations and their class names:

  • TinyPPP_ESP32 (ESP32, all variants): ESP-IDF lwIP PPP via esp_netif, integrated into the Arduino Network API. Sockets: PPPClient_ESP32 (NetworkClient), PPPServer_ESP32 (NetworkServer), PPPUDP_ESP32 (NetworkUDP).
  • TinyPPP_RP2040 (RP2040 / RP2350, Earle Philhower core): TinyPPP engine on a lwIP netif. Sockets: PPPClient_RP2040 (WiFiClient), PPPServer_RP2040 (WiFiServer), PPPUDP_RP2040 (WiFiUDP).
  • TinyPPP_Generic (every board, including the desktop): TinyPPP engine with a small built-in TCP/IP stack (TCP, UDP, ICMP echo, DNS). Sockets: PPPClient_Generic, PPPServer_Generic, PPPUDP_Generic.

The names without a suffix (TinyPPP, PPPClient, PPPServer, PPPUDP) refer to the implementation of the current platform. They are the default choice: the same sketch builds on all platforms. Use the suffixed names to pick an implementation explicitly, e.g. when both kinds are used in one sketch.

Define PPP_PREFER_GENERIC (before the include or as build flag) to make the generic implementation the default on ESP32 and RP2040.

AVR is rejected as default because the generic stack does not fit in its RAM. TinyPPP_Generic.h can still be included there with reduced buffer sizes (see docs/ram.md) at your own risk.

HDLC-like framing for PPP (RFC 1662): FCS-16, byte stuffing and frame reassembly. Platform independent: only depends on the Arduino Print API.

Generic implementation for platforms without lwIP: SAMD and mbed based WiFiNINA boards (Nano 33 IoT, MKR WiFi 1010, Nano RP2040 Connect), the desktop (Arduino-Emulator) and other cores.

The PPP engine is combined with the small TinyPPP IPStack, so PPPClient_Generic, PPPServer_Generic and PPPUDP_Generic work over the link. Received IPv4 packets that are not handled by the stack can be processed with onReceive(), and raw packets can be sent with send().

There is no background task: the link is processed by all socket methods and by loop(). Call loop() regularly when the sketch does not use a socket for a while.
